# Проверка логики и согласованности проекта

## Принятая договорная структура

1. Договорных этапов ровно два.
2. Этап 1 — сценарная логистика ТКО.
3. Этап 2 — региональная пространственная диагностика, предварительная оценка размещения инфраструктуры и визуальные макеты Figma.
4. Исходные тематические части 1–3 распределяются между двумя договорными этапами; исходная часть 4 сокращена до визуального проектирования. Это не четыре договорных этапа.

## Методические решения

- Масса рассчитывается bottom-up по каждому МНО; затем суммируется до НП.
- Старое распределение известной массы НП по МНО, включая равномерный fallback, не используется.
- Официальная масса НП служит только для проверки/возможной калибровки при подтверждённом источнике и сопоставимом периоде.
- Составные графики вывоза разделяются; частоты и все импутации сохраняются в расчётной таблице.
- Кластеризация МНО не обязательна и используется только как техническое ускорение.
- Сценарии S0–S4 рассчитываются только при наличии соответствующих данных; S3 (через МПС) и S4 (фактическая схема) условные.
- В расчёт назначений входят только объекты с подтверждённым действующим статусом и подходящим типом. Инвентаризационный перечень 332 объектов нельзя автоматически приравнивать к 46 действующим объектам; актуальные количества проверить.
- Неизвестная остаточная мощность не равна нулю и не означает подтверждённую допустимость.
- Дорожные расстояния рассчитываются по графу; время — только при наличии пригодных скоростей.
- Линии маршрутов — выборочная визуальная проверка, не фактические маршруты мусоровозов.
- Moran’s I/LISA выполняются только при достаточной применимости; иначе остаются описательные карты.
- MCDA проводится только для одного выбранного типа объекта и после получения применимых нормативных ограничений.
- Сложные location-allocation/p-median модели не входят в обязательный объём.
- Figma-макеты и возможный кликабельный прототип не являются работающим приложением; разработка и UX-валидация исключены.

## Что уточнить при получении данных

- актуальность и версии реестров, EPSG каждого слоя;
- происхождение и период официальной массы по НП;
- соответствие реестров МНО и графиков по ID и типам отходов;
- текущий перечень действующих объектов и причины отличий от инвентаризации;
- проектная/фактическая/остаточная мощность объектов;
- дорожные ограничения, мосты и сезонность;
- выбранный тип объекта для MCDA;
- нормативные источники и применимость каждого ограничения.

## Что не делать

- не подменять пропуски нулями и не удалять записи без журнала;
- не распределять известную массу НП по МНО;
- не считать все инвентаризационные объекты допустимыми назначениями;
- не объявлять участок допустимым при отсутствии критического официального слоя;
- не включать в этапы разработку рабочего веб-приложения, серверной части и UX-тестирование.
